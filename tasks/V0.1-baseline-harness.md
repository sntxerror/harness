# V0.1 — Baseline interactive harness (plan stages 0–2)

Value: a daily-usable local Pi session with intent gating, real PTY and structured questions — safe enough to work in immediately.

**Scope is the workstation.** Server provisioning moved to V0.7 (ADR-040), so nothing here depends on the remote host. The one server item that does not wait is the sudoers time-box: a standing privilege on a host whose work is paused is exactly the failure ADR-038 was written against, so it is revoked now rather than held until V0.7.

## T1 record, 7 August 2026

Executed against the profile layout in `docs/01` §0.2 after operator approval, with the backup
location changed on instruction: it lives in the repository archive rather than in `$HOME`, and
carries no credentials.

| Acceptance clause | Evidence |
| --- | --- |
| Backup restores | `docs/archive/pi-workstation-backup-2026-08-07.tar.gz`, 7.0M. Extracted to a scratch root and compared: **1589 files, `diff -r` reports no differences**. Both `auth.json` files and `agent/sessions/` are excluded by construction; the extracted archive was swept for credential-shaped strings and returned none |
| Launcher selects a distinct extension set | `PI_CODING_AGENT_DIR=~/.pi/profiles/trusted pi list` → "No packages installed"; the default `~/.pi/agent` → `npm:pi-interactive-shell`. Read-only `pi list` wrote nothing into the new root |
| Inventory inside a non-interactive executor | `scripts/executor-inventory.sh`, three views per command — login shell, executor, and each profile's vendored `bin/` |

A tarball rather than a copied tree, because `.gitignore` excludes `*.sqlite` and `*.db` and
`validate-bundle.sh` rejects symlinks anywhere in the bundle; a directory-shaped backup would be
silently partial.

**`agent/sessions/` is excluded, and the reason is a finding rather than a preference.** The first
archive built here included the session transcripts, and sweeping it before commit found one
73-character string of the exact shape `sk-or-v1-` + 64 hex — an OpenRouter API key — inside
`2026-07-10T17-19-36-950Z_019f4d0a…jsonl`. It is not the key currently in `auth.json`, so it is a
previously-used one that a past conversation echoed into its own transcript. Excluding `auth.json`
is therefore not sufficient to make a backup of `~/.pi` safe to commit: **transcripts are
credential-bearing** and nothing in the tree marks them as such. The scope was reduced to the
configuration tree, which is what "the current configuration can be restored" (`docs/01` §0.5)
actually requires, and every future archive of this tree is swept before it is staged.

The key on disk is unaffected by our exclusion and is worth rotating independently; it is recorded
here because the operator needs to know, not because the backup still carries it.

**The acceptance criterion changed in this commit.** "Representative task metrics" was removed from
T1 and is not recorded as done: producing one requires a real task run against a provider, which
needs Pi installed in the profile (T3) and a model pinned and reachable — none of which exist at
Stage 0. It was never satisfiable where it was written. The baseline transcript and metrics belong
with T3, and `docs/01` §0.5's exit condition should be read accordingly. Added in its place is the
vendored-`bin/` clause, which T1 did demonstrate and which the old criterion would have missed.

Provider logins as they stand: `openai-codex` (OAuth, token valid to 12 August 2026, refreshable),
`openrouter` (API key), `gemini` (key). This corrects the recorded survey, which implied the
workstation had OpenRouter only — both routes were live here, so D1 was never constrained by
authentication on this machine.

T4 inspection notes: `docs/reviews/2026-08-06-v0.1-t4-package-pin-inspection.md` (see the 7 August
correction in §3.2). All three pins are accepted with conditions; none rejected.

Three of the five decisions T4 raised are now settled: ADR-037 fixes the privileged-command channel
and its enforcement, ADR-038 time-boxes the harness account's sudo, and the `shellTools` correction
removes the question of whether `interactive_shell` may be admitted before command-level gating —
the alias provides it in config. ADR-039 settles the fourth: pins resolve to latest at refresh time,
so every version recorded across `docs/` was re-resolved on 7 August 2026 and the numbers T4 verified
(24.0.0 and 0.14.0) are now the recorded ones.

**The remaining two closed on 7 August 2026.** `@juicesharp/rpiv-config` and `@juicesharp/rpiv-i18n`
were read on the same terms — downloaded and extracted, nothing installed or executed — and both are
clean: no install scripts, no `bin`, no network, no `eval`. `rpiv-config` is two source files;
`rpiv-i18n` is a soft optional peer that degrades to identity strings when absent and therefore never
needed accepting. The `$EDITOR` temp-file path the review left untraced is the set's only
`child_process` call.

The pin was safe, and is replaced anyway: **ADR-049 makes `ask_user_question` ours**, ~470 native
lines on Pi's `ui.select()`/`ui.input()`, because the `credential` rule had to live in our code
either way and an adapter around 4,960 lines we do not control is more to own than an implementation
that already contains the rule. That also dissolves the `UserQuestionV1` adapter question — there is
no adapter. The tool is built at T6; the two new risks are R-109 (we now track Pi's dialog primitives
ourselves) and R-110 (our typebox must stay pinned to Pi's, or the tool schema drifts silently).

The `rg` finding is worth more than its size, and the recorded version of it was wrong twice. It is not that `command -v rg` succeeds at a prompt and fails in an executor: it fails in **both**, because no system ripgrep exists. Pi ships its own at `$PI_CODING_AGENT_DIR/bin/rg` and invokes it by path, so the command exists for Pi, does not exist for anything Pi spawns, and — the part that matters for this version — **does not exist in a profile root Pi has not yet populated**. T1 created `~/.pi/profiles/trusted` and the divergence is live between the two roots today: `~/.pi/agent` carries `rg` 15.1.0 and `fd` 10.4.2, the trusted root carries neither.

That is a sharper case than the one the survey described. R-003 was written about a profile advertising a command its executor cannot resolve; the vendored layout means two profiles on one machine can disagree about whether a command exists at all, with no shell involved. It is recorded as R-106 and it is the reference case for V0.3-T2's preflight, which must resolve commands per profile root rather than per shell.

The methodological conclusion is unchanged and was vindicated rather than weakened: an inventory taken from an interactive prompt produced a fact that survived two documents and was never true. `scripts/executor-inventory.sh` takes it three ways instead.

Exit: plan Stage 0–2 exit conditions pass on the workstation; a full working session (edit/build/test in this repo) completed inside the harness; the server's `/etc/sudoers.d/90-sntx-nopasswd` removed, since the work it was time-boxed for is now paused until V0.7 (ADR-038); tag `v0.1`.
